# Interaction design

The site answers six questions about the same ant. Each route starts with a
question, lets the reader change a mathematically meaningful input, shows an
observable consequence, then connects that consequence to the proof and source.
Shared navigation preserves the six papers' distinct ownership. The overview
filters routes by geometry, time and local information rather than release date.

## Six interaction loops

| Route | Change | Observe | General argument |
|---|---|---|---|
| One black cell | Placement class and stage | Certified trajectory, support and channel | Exhaustive one-black coverage and Lean theorem |
| Clocks and escape | Square, complete colouring, pose, heading | Exact integer clock, local increment, remaining range, actual exit | Four branch identities and bounded clock range |
| Reading the wake | P104 phase and odd translation classes | Full drift, layer counts, mixed-parity exclusion and theorem hypotheses | Extreme-layer rigidity, period caps, exhaustive classification |
| Local language | Seed, interval endpoints, selected ten-window, rail length | Contained defects, mass inequality, sharp equality, delayed readback | Physical word exclusions, finite-word potential, affine certificates |
| Memory and feedback | Complete seed, time, D, region K, birth filter | Particular black lifetime and qualifying read events | True inverse history, finite-memory continuation, remote-feedback arguments |
| Ports and scattering | Gate/kernel/train/return, rules and spacing | Actual complete field, moving guard, milestones, endpoint hash | Port threshold and protected composition interface |

Playback is opt-in; every dynamic witness also has step or checkpoint controls.
Finite replays use the whole black set. Camera cropping and sampled drawing
affect only the view. A coordinate's successive black lifetimes remain distinct.
Large analytic formulas and certificates use BigInt; large parameters are
evaluated symbolically instead of silently substituted into a short animation.

## Evidence readers can inspect

Three layers recur on each page: the current state and equation, expandable
proof steps explaining the quantifier transition, and the canonical proof,
checker and PDF links. Source hashes identify exported witnesses. A failed
parity condition excludes a proposed wake; passing a necessary screen leaves
realizability open. A rejected collision interface means that construction
lacks the displayed certificate. A finite successful replay verifies its
instance; the all-parameter proof is linked separately.

The wake page exposes the current thin-wake theorem and mixed-wake screen,
including the 76 cases and 83 jobs, instead of presenting an obsolete search
scope. Factor's mass proof remains independent of eventual attraction. Memory
uses actual past history and distinguishes initial black cells from cells newly
born in the simulated future. The port train builder exposes two-rule examples;
the proof covers arbitrary finite compatible trains with certified spacing.

General orbit algorithms, symbolic event macros and the full wake exhaustion
are explained and linked to executable sources. Page interactions focus on
exact objects whose input, result and proof connection can be directly inspected;
they do not offer a browser-wide universal convergence decider.

## Visual and access design

Cream paper, dark ink, teal paths and copper highlights give the six routes a
shared visual vocabulary. Each route has its own input and diagram. Desktop
places a witness beside its controls; narrow screens stack them. Navigation
scrolls horizontally within its container. Native buttons, labelled controls,
focus styles, status text and reduced-motion support accompany canvas views.
Coordinate input and checkpoint controls complement pointer interactions.
Canvas labels describe the view; adjacent text carries the theorem and numeric
result. The grid itself is a visual representation, not a screen-reader proof
interface. Downloads and proof outlines remain available without JavaScript.

Desktop and mobile browser checks exercise input/output changes, formula
rendering, layout, navigation and exact PDF downloads at the deployed URL
prefix. Node tests verify reversible dynamics and proof-specific boundary
cases against exported canonical evidence. Published artifacts stay immutable.
